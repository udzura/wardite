# 旧スタックVM削除の計測

2026年11月19日。比較元は `0c806bc`。削除前後とも既定のEfflorescenceで同じWasmを実行した。

## 計測条件

- macOS 27.2.1 arm64、CRuby 4.0.9（YJIT無効）、Spinel `2026.10.25+6092`（`a2aa05227`、Apple clang 21.0.0）。
- ビルドは同じマシンの別ディレクトリで、出力バイナリを毎回削除して `make spinel` を各4回実行した。プロジェクト既定の `--strict-require -O2` を使用し、Spinel本体の構築は含めていない。
- 実行時間は各条件で1回ウォームアップしてから各9回計測した。各ペア内の実行順は交互に入れ替えた。外部からの計測はプロセス起動から終了まで。MIRディスクキャッシュ、プロファイラは使用していない。
- 整数演算には `benchmark/i32_mix.wat` の `call_mix`、メモリ読み取りには `benchmark/i32_memory.wat` の `array_scan` を使った。どちらもseedは123。各回、i32のラップを考慮した独立の計算式と戻り値を照合した。
- ロード済みVMの計測では各サンプルで新しいプロセスとVMを作り、同じ関数を1回呼んでMIRを準備した。続けて3回呼び、単調時計で測った所要時間を3で割った。Spinelでは両リビジョンに同じRubyドライバをコンパイルした。

## 結果

中央値。差は削除前に対する増減で、時間のマイナスは短縮を表す。CRubyの起動計測には `ruby --disable-gems --disable-yjit -Ilib -rwardite -e ''` を使った。

| 計測対象 | 削除前 | 削除後 | 差 |
| --- | ---: | ---: | ---: |
| Spinelフルビルド | 23.071 s | 19.787 s | -14.2% |
| Spinel実行ファイル | 5,241,928 B | 4,991,320 B | −4.8% |
| CRuby起動＋ `require "wardite"` | 24.847 ms | 21.902 ms | -11.9% |
| Spinel CLI · `call_mix` × 0 | 4.465 ms | 4.417 ms | -1.1% |
| Spinel CLI · `call_mix` × 100,000 | 6.234 ms | 6.115 ms | -1.9% |
| Spinel CLI · `array_scan` × 1,000 | 9.838 ms | 9.912 ms | +0.8% |
| CRuby CLI · `call_mix` × 100,000 | 117.440 ms | 114.806 ms | -2.2% |
| CRuby CLI · `array_scan` × 1,000 | 301.837 ms | 298.209 ms | -1.2% |
| Spinel ロード済み · `call_mix` × 30,000 | 0.640 ms | 0.647 ms | +1.0% |
| Spinel ロード済み · `array_scan` × 300 | 1.750 ms | 1.839 ms | +5.0% |
| CRuby ロード済み · `call_mix` × 30,000 | 19.756 ms | 20.017 ms | +1.3% |
| CRuby ロード済み · `array_scan` × 300 | 74.809 ms | 75.044 ms | +0.3% |

Spinelのビルドは全4組で短縮し、中央値で3.28秒短くなった。CRubyではライブラリ読み込みまでが約2.95 ms短縮した。ロード済みVMでは、整数演算・メモリ走査のいずれも高速化を確認できなかった。Spinelのメモリ走査は9組すべてで削除後のほうが遅かった。

### Spinelのメモリ走査の再測定

同じ `array_scan` を20,000周に延ばし、各1回ウォームアップ後に順序を交互にして15組を測った。CLIはプロセス全体、ロード済みVMは上記と同じく3回の平均を1サンプルとした。

| 計測対象 | 削除前 | 削除後 | 差 |
| --- | ---: | ---: | ---: |
| 配布用CLI | 126.267 ms | 125.838 ms | -0.3% |
| ロード済みVM（計測用実行ファイル） | 117.455 ms | 122.826 ms | +4.6% |

長い走査でも計測用バイナリでは4.6%の遅延が再現した。配布用CLIでの差は0.3%だった。Spinelはエントリポイントごとにネイティブコードを生成するため、この結果から配布用CLIでも同じ遅延が起きるとは言えない。遅延の原因は特定していない。

## 動作確認

Spinelネイティブ版を指定した全334テスト（37,298 assertions）が成功し、省略は0件。`bundle exec rake check` と `bundle exec rake parity` も成功した。命令検証では436件をWasmtimeと照合し、CRuby・Spinelの両方で既定の最適化と全最適化無効の条件を確認した。
