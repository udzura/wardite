# ADR 0026: 未使用のMIRスロットを除いてフレームを小さくする

- **状態** 提案
- **日付** 2026-11-21
- **関連** [ADR 0013（フレーム確保の費用）](0013-efflorescence-frame-acquisition.md)、[ADR 0025（ループJIT）](0025-efflorescence-jit-numeric-types-and-sieve.md)

## 背景

MIRの構築時にはスロットを末尾に割り当てる。COPYや演算を融合して一時値への参照が消えても、フレームの初期値配列と型表にはそのスロットが残る。新規フレームは初期値配列を複製し、ループJITは入口と出口でレジスタ値を受け渡す。どちらの費用にも関数のスロット数が影響する。[フレームの実装](../../lib/wardite/efflorescence/ir.rb)・[ループJITとの受け渡し](../../lib/wardite/efflorescence/spinel_jit.rb)

Wardite `10764d1` の最適化後MIRを調べると、Base64 encodeでは452スロット中121、decodeでは684中212、PNGの輝度変換では47中14が、引数・ローカル以外で読み書きともに0だった。これは圧縮候補の静的な個数で、実行時間への寄与はベンチで確かめる。

## 決定

関数ごとの命令最適化を終えた段階で、引数・宣言ローカルの番号を固定し、残りのうち一度も参照されない一時・定数スロットを取り除く。読み出しが0でも書き込み先になっていれば残す。残った各スロットには元の順序で一意な新番号を与える。ADR 0013で提案した、生存区間の重ならない一時値に同じ番号を割り当てる手法は別段階で判断する。

命令の入力と出力に加え、呼び出し引数、メモリ操作、throwとcatchのペイロード、例外参照の格納先まで数えてから対応表を作る。`Function#replace_register_references!` の書き換え対象と照合し、型表、初期値、定数の番号も同じ対応表で組み直す。圧縮後にレジスタを検証し、その配置からflat MIR、呼び出しの副表、JITコードを生成する。MIR2キャッシュのコード版を更新し、復元時は保存済みの配置を使う。

## 検証と採用条件

- **フレームを頻繁に新規作成するベンチを主測定にする。** 未使用スロットが多い関数を深く再帰させ、同じ関数のフレームが同時に多数生きる入力を使う。同じゲスト実行中に再帰から戻ってもう一度同じ深さまで呼び出し、プールを再利用する場合も測る。両者で新規作成数・取得数・複製したスロット総数を数え、計数を外してJIT無効の実行時間とピークRSSを比較する。
- 実利用の対照にはRubyのWasm起動を使う。ADR 0013の計測では取得638,683回に対して新規作成は1,096回だった。短い呼び出しを繰り返す場合にも効果が及ぶかを調べ、MIR生成時間とキャッシュサイズを併記する。
- 呼び出し、副表だけから参照する値、初期値を持つ定数、catchで受け取る値を含むケースで、圧縮の有無、キャッシュ生成・復元、JIT有効・無効の結果とtrapを照合する。新規作成時の複製量が減り、時間またはメモリの改善が再現し、通常の起動や再利用経路に目立った退行がないことを採用条件とする。
