# ADR 0009: MIR2キャッシュの整合性検査モード

- **状態** 提案
- **日付** 2026-11-12
- **前提** [ruby.wasm対応フェーズ2](0008-efflorescence-ruby-wasm-phase2.md)、[MIR2キャッシュの実装記録](../efflorescence-mir2-cache.md)

## 背景

[MIRCache#read](../../lib/wardite/efflorescence/mir_cache.rb) はキャッシュヒットのたびに、ペイロード全体のSHA-256を計算してヘッダーの値と照合する。Ruby 4.0.9のWasmではペイロードが約79 MiBある。

Spinel版（`6f1a2c259`、`-O2`）でキャッシュヒット時の起動を `sample` で1回プロファイルした（1 ms間隔、1151サンプル。プロセス全体は約1.5秒）。`sp_crypto_sha256_block` が121サンプルで、取得できた区間の約1割を占めた。

SHA-256はここでは破損の検出に使っている。入力の信頼は、キャッシュディレクトリを管理する実行ユーザーに置く（ADR 0008）。また、読み込み時にはダイジェストとは別に、opcode、参照index、分岐先、レジスタ型の構造検査を全関数に対して行う。

## 決定

整合性検査を2つのモードから選べるようにする。どちらのモードでも構造検査は省略しない。

| モード | 検査する内容 | 用途 |
|---|---|---|
| `sha256` | ペイロード全体のSHA-256（現行と同じ） | 共有ストレージ上のキャッシュ、破損を疑うときの確認 |
| `checksum` | ペイロード長と、標本ブロックのSHA-256 | 通常の起動 |

既定は `checksum` とする。`sha256` は `--mir-cache-verify sha256` で選ぶ。Ruby APIでは `mir_cache_verify: :sha256` を渡す。

### 簡易チェックサムの定義

`checksum` モードは、ペイロードから次のブロックを順に連結したバイト列のSHA-256を使う。

1. ペイロード長（little-endianの符号なし64ビット）
2. 先頭64 KiB
3. 1 MiBごとの境界から4 KiB
4. 末尾64 KiB

ペイロードが128 KiB以下の場合は全体をハッシュする。79 MiBのペイロードでは、ハッシュする量は約450 KiBになる。

既存の `Digest::SHA256` だけで実装でき、CRubyとSpinelで同じ値になる。CRC32などの別アルゴリズムは、Spinel側の実装を新たに必要とするため採用しない。

標本に含まれない位置の破損は、このモードでは検出できない。その場合は構造検査で検出するか、検出できずに誤った命令を実行する。この制限を利用者向けドキュメントに記載する。

### ファイル形式

ヘッダーを次の並びにし、`FORMAT_VERSION` を更新する。

| フィールド | 大きさ |
|---|---:|
| マジック、バージョン、キー（現行どおり） | 現行どおり |
| ペイロード長 | 8バイト |
| 簡易チェックサム | 32バイト |
| 全体のSHA-256 | 32バイト |
| ペイロード | 可変 |

保存時は両方のダイジェストを計算して書く。読み込み時は、選ばれたモードのダイジェストだけを計算して照合する。ペイロード長はどちらのモードでもファイルサイズと照合する。

モードはキャッシュキーに含めない。同じファイルをどちらのモードでも読めるようにする。

### 対象外

- キャッシュキーに使うWasm全体のSHA-256（約17 MiB）は変更しない。キーが誤ると別のWasm用の命令列を実行するため、ここは全体のハッシュを維持する。
- OSのSHA-256実装をFFIで呼ぶ高速化は、このADRでは決めない。採用すれば `sha256` モードとキー計算の両方が速くなるため、`checksum` モードの導入後に計測して判断する。

## 検証

- 両モードで、ヒット・ミス・保存の各経路がキャッシュ無効時と同じ結果になる。
- 末尾の切り詰め、ヘッダーの各フィールドの改変、標本ブロック内の1バイト改変を、両モードでミスとして扱う。
- 標本ブロック外の1バイト改変を `sha256` モードでミスとして扱う。`checksum` モードでは、構造検査で検出できる改変（不正なopcode、範囲外のindex）がミスになることを確認する。
- 旧形式のファイルをミスとして扱い、再生成する。
- CRubyが保存したファイルとSpinelが保存したファイルで、それぞれのホスト上のダイジェストが一致する。

計測は、Ruby 4.0.9のWasmでキャッシュヒットの `load_from_buffer` とプロセス全体を、変更前・`sha256`・`checksum` の3条件で各3回以上、別プロセスで行う。OSのファイルキャッシュの状態を記録する。

## 受け入れ条件

- `checksum` モードで、`load_from_buffer` が変更前より短くなることを計測で示す。
- `sha256` モードの時間が変更前から退行しない。
- [verify_ruby_wasm.rb](../../scripts/verify_ruby_wasm.rb) の3ケースが、両モードでWasmtimeと一致する。
- CRubyのtest・型チェック・parityと、Spinelの回帰試験が通る。
