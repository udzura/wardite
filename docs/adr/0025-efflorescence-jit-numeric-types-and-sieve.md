# ADR 0025: 関数JITをi64、f32/f64の順に拡張してから篩法を高速化する

- **状態** 第1段階（i64）と第2段階（f32/f64）は実装・検証済み。第3段階（篩法）は計画中
- **日付** 2026-11-21
- **前提** [ADR 0024（関数JITとi32の試し割り）](0024-efflorescence-function-jit-and-trial-division.md)

## 決定

Spinel版の関数JITは **① i64 → ② f32/f64 → ③ 篩法の高速化** の順に進める。最終目標は、wardite-benchesのRust版 `count_primes_sieve` を変更せずに速くすることである。

最初の2段階では、呼び出しやメモリ操作を含まない関数で、各型の引数・単一結果、ローカル、定数、数値演算、比較、型変換を扱う。整数と浮動小数点の間の変換は第2段階で扱う。先に関数の入口と出口で値とtrapを検証しておくと、第3段階では、同じコード生成器を使ってループに渡す値、メモリへの副作用、VMへの復帰位置に集中できる。

### 1. i64の関数JITを仕上げる

ADR 0024の64ビットスロットと一部の演算を出発点に、関数境界でも64ビットすべてを受け渡す。対象命令は既存VMのi64数値命令とi32との整数変換に合わせる。符号の有無を区別した比較・除算・剰余、シフト、オーバーフロー時の折り返し、ゼロ除算と符号付き除算のオーバーフローを照合する。[既存VMのi64仕様](0004-efflorescence-m4-i64.md)

完了時には、上位ビットが立ったi64引数・結果を含む命令別のケースでJITとVMの値・trapが一致し、既存ベンチの `alu` と `division` がネイティブで完走することを確認する。[i64ベンチ](../../benchmark/i64_m4.wat)

**実装結果（2026-11-21）**　呼び出し側で引数を8バイトずつバッファに並べ、生成コードは起動時に各引数をMIRスロットに読み込む。正常終了時だけ先頭8バイトに結果を書く。これにより引数なしの定数関数、i32とi64の混在、レジスタに収まらない引数も同じ呼び出し規約で扱う。ゼロ除算と符号付き除算の `INT64_MIN / -1` は元の引数でVMに戻してtrapにする。`INT64_MIN % -1` はネイティブで0を返す。[呼び出し規約](../../lib/wardite/efflorescence/spinel_jit.rb)・[コード生成](../../lib/wardite/efflorescence/spinel_jit/aarch64.rb)

既存のi64演算・整数変換35命令について、固定シードの入力と境界値を含む17,675ケースを、同じSpinel workerのJIT無効・有効で照合した。全35関数がコンパイルされ、VMへの復帰は期待したtrapの65ケースだけだった。[参照値の生成](../../test/support/efflorescence_m4_alu_cases.rb)・[ネイティブ実行の照合](../../test/e2e/spinel_m4_test.rb)

macOS 27.2.1 arm64、Spinel `072516af1` の `-O2` ビルドで計測した。seedは123。Wasmtimeと結果の64ビットを照合し、別プロセスのトレースでネイティブ実行を確認した。表はCLI起動・Wasmロード・初回コンパイルを含む全体時間の中央値。JIT無効・有効の実行順を交互にし、各2回ウォームアップして9回ずつ計測した。[計測スクリプト](../../benchmark/measure_i64_jit.rb)

| 関数 | 反復数 | JIT無効 | JIT有効 | 無効 / 有効 |
|---|---:|---:|---:|---:|
| `alu` | 200,000 | 11.320 ms | 5.681 ms | 1.99倍 |
| `division` | 200,000 | 29.895 ms | 5.869 ms | 5.09倍 |
| `alu` | 2,000,000 | 62.681 ms | 8.554 ms | 7.33倍 |
| `division` | 2,000,000 | 245.209 ms | 10.035 ms | 24.44倍 |

`bin/test-spinel-jit` でビルドした場合は `ruby benchmark/measure_i64_jit.rb build/spinel-jit-test/wardite 2000000` で再計測できる。

### 2. f32とf64の関数JITを仕上げる

両方の幅で引数・結果と演算を扱い、混合型の変換まで実装する。各f32演算で単精度に丸める。コピーやreinterpretではNaNのpayloadと符号付きゼロを含むビット列を保存し、算術で生じるNaNはWasmが許す範囲で照合する。浮動小数点から整数への変換では、trapを起こす命令と飽和変換の境界を区別する。[既存VMの浮動小数点仕様](0005-efflorescence-m5-floating-point.md)

完了時には、両方の幅の値と境界値を命令別に検証し、`float_alu` と `float_convert` がネイティブで完走してVMと同じ結果を返すことを確認する。[浮動小数点ベンチ](../../benchmark/float_m5.wat)

**実装結果（2026-11-21）**　引数・戻り値・MIRスロットは第1段階と同じバッファでビット列を受け渡す。演算時にだけAArch64の単精度・倍精度レジスタを使う。浮動小数点を使う関数に入るときにホストのFPCR・FPSRを保存し、最近接偶数丸め、非正規化数の保持、算術NaNの正規化を指定する。正常終了時とVMへの復帰時に元の設定とフラグを戻す。整数へのtruncは変換命令のinvalidフラグを検査してVMにtrapを引き継ぎ、trunc_satは同じ変換命令の飽和結果を返す。[浮動小数点コード生成](../../lib/wardite/efflorescence/spinel_jit/aarch64_float.rb)

算術・比較・変換70命令の385ケースで、値・ビット列・trapをJIT有効時と無効時に照合した。3種類の最適化設定すべてで、プロファイル無効時は全385関数がコンパイルされ、VMへの復帰は期待した40件のtrapだけだった。[入力と期待値](../../test/support/efflorescence_m5_cases.rb)・[トレースの検証](../../test/e2e/spinel_m5_test.rb)

macOS 27.2.1 arm64、Spinel `072516af1` の `-O2` ビルドで、第1段階と同じくCLI起動からの中央値を取った（実行順を交替、各2回ウォームアップ・9回計測）。マンデルブロはwardite-benches `921a692` のRust版Wasmを両精度でそのまま実行した。4関数すべてでネイティブ実行をトレースで確認し、JIT有効・無効ともにWasmtimeと結果が一致した。[マンデルブロの実装](https://github.com/udzura/wardite-benches/blob/921a69220eaad620ecc033013f4171e5b21eb8e7/rust/examples/mandelbrot.rs)・[計測スクリプト](../../benchmark/measure_float_jit.rb)

| 関数 | 入力 | 結果 | JIT無効 | JIT有効 | 無効 / 有効 |
|---|---|---:|---:|---:|---:|
| `mandelbrot_f32` | 200×150、最大100反復 | 745,736 | 2,791.666 ms | 21.575 ms | 129.39倍 |
| `mandelbrot_f64` | 200×150、最大100反復 | 747,800 | 2,810.988 ms | 22.064 ms | 127.40倍 |
| `float_alu` | 200,000反復、seed 123 | 1,075,838,977 | 184.764 ms | 9.946 ms | 18.58倍 |
| `float_convert` | 200,000反復、seed 123 | 20,000,100,123 | 99.431 ms | 9.369 ms | 10.61倍 |

wardite-benchesを隣のディレクトリにビルドした環境では、`ruby benchmark/measure_float_jit.rb build/spinel-float-jit/wardite` で4ケースを再計測できる。第2引数に別の `mandelbrot.wasm` のパスも指定できる。

### 3. 元の篩のループを切り出して高速化する

現行の `count_primes_sieve(1_000_000)` はVMで `78,498` を返す。呼び出し先を含むプロファイルでは、`CALL` が8回、`I32_LOAD8_U` が500,500回、`I32_STORE8` が811,069回だった。確保・解放はVMに任せ、反復全体をMIRから切り出してネイティブ実行する（loop outlining）。JIT有効時に解釈中の親関数から切り出した区間に入る経路を設ける。JIT無効時は元のMIRを実行する。[Rustの篩](https://github.com/udzura/wardite-benches/blob/921a69220eaad620ecc033013f4171e5b21eb8e7/rust/examples/count_primes.rs#L22-L44)

1. 末尾の未マーク要素の集計から始める。確保後の線形メモリの先頭と現在のバイト長を渡し、境界検査付きの `load8_u` を実装する。読み取り専用なので、途中でVMに戻る場合も集計の入口からやり直せる。
2. 倍数に印を付ける内側のループに `store8` を加える。書き込み前に全反復のアクセス範囲を検証するか、書き込み済みの状態と必要なローカルを保持して該当のMIR命令からVMに戻る。Rustの添字検査の失敗とWasmのメモリ範囲外trapをそれぞれ元の動作に合わせる。

完了条件は、元のWasmで対象ループのネイティブ実行をトレースで確認し、同じSpinelバイナリ・入力でJIT有効時と無効時の結果を照合したうえで、篩全体の実時間が短縮すること。計時はトレースとプロファイラを外し、コンパイルとVMとの受け渡しを含めて繰り返す。小さい入力も併記し、境界をまたぐコストが見えるようにする。
