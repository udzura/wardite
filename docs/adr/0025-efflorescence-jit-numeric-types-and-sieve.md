# ADR 0025: 関数JITをi64、f32/f64の順に拡張してから篩法を高速化する

- **状態** 実装順を採用。以下の3段階は未実装
- **日付** 2026-11-21
- **前提** [ADR 0024（関数JITとi32の試し割り）](0024-efflorescence-function-jit-and-trial-division.md)

## 決定

Spinel版の関数JITは **① i64 → ② f32/f64 → ③ 篩法の高速化** の順に進める。最終目標は、wardite-benchesのRust版 `count_primes_sieve` を変更せずに速くすることである。

最初の2段階では、呼び出しやメモリ操作を含まない関数で、各型の引数・単一結果、ローカル、定数、数値演算、比較、型変換を扱う。整数と浮動小数点の間の変換は第2段階で扱う。先に関数の入口と出口で値とtrapを検証しておくと、第3段階では、同じコード生成器を使ってループに渡す値、メモリへの副作用、VMへの復帰位置に集中できる。

### 1. i64の関数JITを仕上げる

ADR 0024の64ビットスロットと一部の演算を出発点に、関数境界でも64ビットすべてを受け渡す。対象命令は既存VMのi64数値命令とi32との整数変換に合わせる。符号の有無を区別した比較・除算・剰余、シフト、オーバーフロー時の折り返し、ゼロ除算と符号付き除算のオーバーフローを照合する。[既存VMのi64仕様](0004-efflorescence-m4-i64.md)

完了時には、上位ビットが立ったi64引数・結果を含む命令別のケースでJITとVMの値・trapが一致し、既存ベンチの `alu` と `division` がネイティブで完走することを確認する。[i64ベンチ](../../benchmark/i64_m4.wat)

### 2. f32とf64の関数JITを仕上げる

両方の幅で引数・結果と演算を扱い、混合型の変換まで実装する。各f32演算で単精度に丸める。コピーやreinterpretではNaNのpayloadと符号付きゼロを含むビット列を保存し、算術で生じるNaNはWasmが許す範囲で照合する。浮動小数点から整数への変換では、trapを起こす命令と飽和変換の境界を区別する。[既存VMの浮動小数点仕様](0005-efflorescence-m5-floating-point.md)

完了時には、両方の幅の値と境界値を命令別に検証し、`float_alu` と `float_convert` がネイティブで完走してVMと同じ結果を返すことを確認する。[浮動小数点ベンチ](../../benchmark/float_m5.wat)

### 3. 元の篩のループを切り出して高速化する

現行の `count_primes_sieve(1_000_000)` はVMで `78,498` を返す。呼び出し先を含むプロファイルでは、`CALL` が8回、`I32_LOAD8_U` が500,500回、`I32_STORE8` が811,069回だった。確保・解放はVMに任せ、反復全体をMIRから切り出してネイティブ実行する（loop outlining）。JIT有効時に解釈中の親関数から切り出した区間に入る経路を設ける。JIT無効時は元のMIRを実行する。[Rustの篩](https://github.com/udzura/wardite-benches/blob/921a69220eaad620ecc033013f4171e5b21eb8e7/rust/examples/count_primes.rs#L22-L44)

1. 末尾の未マーク要素の集計から始める。確保後の線形メモリの先頭と現在のバイト長を渡し、境界検査付きの `load8_u` を実装する。読み取り専用なので、途中でVMに戻る場合も集計の入口からやり直せる。
2. 倍数に印を付ける内側のループに `store8` を加える。書き込み前に全反復のアクセス範囲を検証するか、書き込み済みの状態と必要なローカルを保持して該当のMIR命令からVMに戻る。Rustの添字検査の失敗とWasmのメモリ範囲外trapをそれぞれ元の動作に合わせる。

完了条件は、元のWasmで対象ループのネイティブ実行をトレースで確認し、同じSpinelバイナリ・入力でJIT有効時と無効時の結果を照合したうえで、篩全体の実時間が短縮すること。計時はトレースとプロファイラを外し、コンパイルとVMとの受け渡しを含めて繰り返す。小さい入力も併記し、境界をまたぐコストが見えるようにする。
