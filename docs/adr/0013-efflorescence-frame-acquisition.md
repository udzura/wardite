# ADR 0013: Efflorescenceのフレーム確保の費用とフレームの大きさ

- **状態** 提案
- **日付** 2026-11-12
- **前提** [ruby.wasm対応フェーズ2](0008-efflorescence-ruby-wasm-phase2.md)の「7. ゲスト実行時間の改善」、[callコストの調査](../efflorescence-call-investigation.md)、[フレーム再利用時の初期化の軽量化](../efflorescence-register-initialization.md)

## 背景

Wasm間の呼び出しでは、[FramePool#acquire](../../lib/wardite/efflorescence/ir.rb) が関数ごとの空き一覧からフレームを取り出し、`Frame#reset` が非引数ローカルを0に戻す。空きがなければ `Frame.new` が初期レジスタのテンプレートを複製する。

Ruby 4.0.9のWasmを `--disable-gems -e 'puts RUBY_DESCRIPTION'` で起動して計測した。

### Spinel版のプロファイル

キャッシュヒットの起動を `sample` で1回取得した（1 ms間隔、1151サンプル）。ゲスト実行（`VM#execute`）は743サンプルで、`sp_FramePool_acquire` はそのうち30サンプル（約4%）だった。`Frame#reset` はこの関数にインライン化されている。

### CRuby版の実行回数

`--mir-profile` と、`FramePool#acquire` に計数を加えたスクリプトで数えた。

| 項目 | 値 |
|---|---:|
| 実行したMIR命令 | 66,500,266 |
| `CALL` | 586,626（0.88%） |
| `CALL_INDIRECT` 経由の関数への入場 | 52,056 |
| `RETURN` | 638,683（0.96%） |
| フレームの取得（`acquire`） | 638,683 |
| 新規に作ったフレーム | 1,096 |
| 呼ばれた関数 | 943（定義された6049関数のうち） |
| 取得1回あたりの非引数ローカル数（平均） | 7.13 |
| `reset` が0に戻したスロットの総数 | 4,556,344 |
| 取得1回あたりのレジスタ数（平均） | 675.13 |

呼び出しの90%は121個の関数が占める。非引数ローカルが16個以下の呼び出しが92.5%だった。

### 読み取れること

- フレームの取得は約64万回で、新規作成は1,096回にとどまる。空き一覧の再利用は機能している。
- `reset` の0埋めは約456万回の書き込みで、実行命令数の約7%にあたる回数。1回の取得あたりでは平均7スロットと小さい。
- 取得1回あたりのレジスタ数は平均675個で、8バイトの整数なら約5.4 KiBになる。ローカル（平均7個）に比べて一時レジスタと定数レジスタが大半を占める。
- 最も多く呼ばれた関数（22,720回）はレジスタ759個、ローカル11個だった。

フレーム確保そのものの費用は、ゲスト実行の約4%が上限になる。一方で、フレームが大きいことは、キャッシュミス、MIR2キャッシュのファイルサイズ（関数ごとにレジスタ型1バイトと初期値8バイトをレジスタ数だけ保存する）、ピークRSSに影響しうる。ただし、フレームの大きさが実行時間にどれだけ効いているかは未計測である。

## 決定

フレーム確保の経路の作り直しは行わない。まずレジスタの内訳を計測し、その結果で、レジスタの詰め直しによってフレームを小さくするかを決める。

### 段階1: レジスタの内訳を計測する

呼ばれた943関数について、レジスタを引数、非引数ローカル、定数、一時の4種に分けて数える。呼び出し回数で重み付けした平均と、関数ごとの静的な分布の両方を記録する。

あわせて、MIR2キャッシュのペイロードのうち、レジスタ型と初期レジスタが占めるバイト数を求める。

### 段階2: 一時レジスタの詰め直し

段階1で一時レジスタが過半を占める場合に進める。

最適化後のMIRに対して関数ごとに次を行う。

1. 基本ブロックの制御フロー（ループと例外辺を含む）の上で、各一時レジスタの生存区間を求める。
2. 生存区間が重ならない一時レジスタに同じスロットを割り当てる。スロットは番号の小さい順に再利用する。
3. 引数、非引数ローカル、定数のスロットは変えない。定数は初期化後に書き込まないという既存の契約を保つ。
4. `exnref` のレジスタは整数のレジスタと別に扱い、互いに同じスロットへ割り当てない。
5. 命令、呼び出し引数、メモリ・例外の参照表にあるレジスタ番号を書き換える。

この処理は [RegisterValidation](../../lib/wardite/efflorescence/register_validation.rb) の前に置く。詰め直した後のMIRが「読む前に必ず書く」ことを、既存の検証でそのまま確かめる。フレームの再利用時に一時レジスタを初期化しない現行の方式は変えない。

`--mir-disable` に `compact` を追加し、個別に無効化できるようにする。MIRの内容が変わるため `MIRCache::CODE_VERSION` を更新する。

MIR変換の時間が増えるので、キャッシュミス時のビルド時間も計測する。

### 行わないこと

- **0埋めの範囲をさらに絞る**: 読む前に必ず書かれるローカルを解析して0埋めを省く案。1回の取得あたり平均7スロットで、省ける書き込みは実行命令数の数%にとどまる。解析結果をキャッシュに保存する形式変更も必要になるため、採用しない。
- **レジスタを1本の連続した配列に置く**: フレームごとの配列をやめ、基準位置からの相対で読み書きする案。取得と解放は軽くなるが、全命令のレジスタ参照に加算が増える。`CALL` と `RETURN` は実行命令の2%未満なので、採用しない。
- **空き一覧の構造を変える**: フレームに次の空きへの参照を持たせる案。取得は64万回で、得られる差は小さい。採用しない。

### 対象外

`VM#execute` は公開呼び出しのたびに、全関数ぶんの `FramePool` を作る（このWasmでは6049個）。`_start` を1回呼ぶ起動では問題にならない。公開関数を繰り返し呼ぶ利用形態での費用は、このADRでは扱わない。

## 検証

- 詰め直しの有無で、436フィクスチャのparityがCRubyとSpinelで通る。
- ループをまたいで生存するレジスタ、例外ハンドラへ渡るレジスタ、`br_table` の合流、多値のブロックで、スロットを共有しないことを試験する。
- 詰め直し後のMIRが `RegisterValidation` を通る。意図的に生存区間の重なるレジスタを同じスロットにした場合に、検証またはparityで検出できることを確認する。
- `--mir-disable compact` で詰め直し前と同じMIRになる。
- `--mir-dump` の出力で、関数ごとのレジスタ数が減っていることを確認する。

計測は、Ruby 4.0.9のWasmで、詰め直しの有無それぞれについて次を各3回以上、別プロセスで行う。

- キャッシュヒット時の `load_from_buffer`、ゲスト実行時間、プロセス全体、ピークRSS
- キャッシュミス時のMIR2生成時間
- MIR2キャッシュのファイルサイズ
- 取得1回あたりのレジスタ数（平均）

既存のi32、i64、float、call、Storeのベンチマークで小さなモジュールへの影響も調べる。

## 実装順

| 順 | 作業 | 確認 |
|---|---|---|
| 1 | レジスタの内訳と、キャッシュ中のレジスタ関連のバイト数を計測する | 一時レジスタが過半でなければ中止し、結果をこのADRに追記する |
| 2 | 生存区間の解析と詰め直しを実装する | 上記の試験とparityが通る |
| 3 | 計測とドキュメント | 上記の項目を記録する |

## 受け入れ条件

- 取得1回あたりのレジスタ数とMIR2キャッシュのファイルサイズが減ることを計測で示す。
- Ruby 4.0.9のゲスト実行時間が退行しない。短縮した場合はその値を記録する。
- キャッシュミス時のMIR2生成時間の増加を記録する。
- [verify_ruby_wasm.rb](../../scripts/verify_ruby_wasm.rb) の3ケースがWasmtimeと一致する。
- CRubyのtest・型チェック・parityと、Spinelの回帰試験が通る。
